# Бот для новых улучшенных подарков Telegram

Находит только что улучшенные (upgraded) подарки во всех коллекциях и присылает их в личку бота.

## Как это работает

У каждого улучшенного подарка есть ссылка `t.me/nft/<Коллекция>-<N>`, а `N` растёт по порядку улучшений.
Поэтому «новый подарок» — это подарок с номером `last+1`:

1. **Watcher** (Telethon, юзер-аккаунт) берёт список коллекций из магазина подарков.
2. При первом запуске бинарным поиском находит текущий последний номер каждой коллекции и запоминает его (старые подарки не рассылаются).
3. Затем по кругу спрашивает `payments.getUniqueStarGift` для `last+1`. Если подарок есть, он отправляется подписчикам, и проверяется следующий номер.
4. **Бот** (aiogram) рассылает подарок тем, чьи фильтры подходят. Подписчики и позиции хранятся в SQLite, так что после перезапуска дублей нет.

## Установка

```bash
cd gift-bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env     # заполни API_ID, API_HASH, BOT_TOKEN
python login.py          # один раз: телефон + код из Telegram (юзер-аккаунт)
python main.py
```

- `API_ID` / `API_HASH`: https://my.telegram.org → API development tools
- `BOT_TOKEN`: у @BotFather
- Лучше использовать отдельный аккаунт, а не основной.

Первый запуск занимает несколько минут: идёт поиск стартовых номеров (около 15 запросов на коллекцию). Дальше позиции берутся из БД.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | включить уведомления |
| `/stop` | выключить |
| `/filters` | показать фильтры |
| `/list` | список отслеживаемых коллекций |
| `/collections Plush Pepe, Durov's Cap` | только эти коллекции (`/collections all` — все) |
| `/maxnum 1000` | только подарки с номером ≤ 1000 (`off` — убрать) |
| `/rarity 2` | только модели с редкостью ≤ 2% (`off` — убрать) |
| `/original on` | только подарки с подписью «Подарок от … для …» (`off` — убрать) |
| `/reset` | сбросить все фильтры |

## Настройка и ограничения

- **`REQUESTS_PER_SECOND`**: полный круг по коллекциям занимает `коллекций / RPS` секунд. Чем выше значение, тем быстрее реакция, но выше риск FloodWait (он обрабатывается автоматически, бот ждёт и продолжает).
- **Список коллекций** берётся из магазина подарков (только те, что можно улучшить). Если нужной коллекции нет в `/list`, добавь её в `EXTRA_COLLECTIONS`.
- **Slug** строится из названия без пробелов и знаков (`Durov's Cap` → `DurovsCap`). Если у какой-то коллекции ссылка выглядит иначе, подарки из неё не найдутся. Напиши, и я добавлю ручное соответствие.
- Если при запуске ошибка `AttributeError ... GetUniqueStarGiftRequest`, обнови Telethon: `pip install -U telethon`.
- Бот присылает превью подарка через предпросмотр ссылки `t.me/nft/...`.


## Исправление владельца подарка (v2)

Владелец теперь извлекается из `owner_id` самого уникального подарка, а публичный
username ищется среди `users`, которые Telegram возвращает вместе с ответом
`payments.getUniqueStarGift`. Ранее код пытался читать только `owner_name` и
`owner_id.user_id`, поэтому реальный `@username` терялся. В уведомлении
показывается кликабельный `@username`, если Telegram вернул его.

Важно: Telegram не всегда отдаёт данные владельца. Если профиль/владелец скрыт
или отсутствует в ответе API, бот не может гарантированно получить username.
